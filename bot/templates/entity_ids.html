⚙️ Как считается матчинг

Каждая связь источник→ЖК получает confidence из сигналов, которые реально удалось проверить: имя — точное совпадение (+{{ thresholds.w_name }}) ИЛИ похожее по pg_trgm similarity ≥ {{ thresholds.fuzzy }} (fuzzy-ступень, вес линейно растёт от +{{ thresholds.w_name_fuzzy_min }} до +{{ thresholds.w_name }} — ловит ребрендинг/опечатки между источниками), гео-близость в пределах {{ thresholds.geo_radius_m|int }} м (+{{ thresholds.w_geo }}), совпадение застройщика (+{{ thresholds.w_developer }}), пересечение токенов адреса (+{{ thresholds.w_address }}). confidence ≥ {{ thresholds.auto }} — связь пишется в спайн автоматически; {{ thresholds.review }}–{{ thresholds.auto }} — уходит в очередь ниже (НЕ в спайн, пока не подтверждена руками); ниже {{ thresholds.review }} — не создаётся вовсе. Первый источник, принёсший новый ЖК (а не совпавший с существующим), пишется с confidence 1.0 — там неоднозначности нет (seed_source). Если source_id уже привязан к ДРУГОМУ ЖК — новый вариант не перезаписывает молча, тоже уходит в очередь как конфликт. Руками отклонённые пары запоминаются (complex_source_link_rejections) — повторно не предлагаются.

✂️ Кандидаты на расшивку ({{ split_candidates|length }})

Обратная задача дублям — один complex_id на самом деле описывает несколько разных зданий/очередей (см. docs/entity_resolution_plan.md, "политика гранулярности ЖК" и "расшивка как review-очередь"). Многоуровневый детектор (split_detect.py) собирает evidence из нескольких источников разом — krisha_deadlines (срок сдачи по очередям), homeportal_blocks (объекты Госстройконтроля того же ЖК), apartment_listings_geo_clusters (гео-кластеры объявлений Крыши + явный маркер в тексте); Korter/Homsters проверены живьём (2026-08-13) — обе площадки не отдают пер-блочных данных на карточке ЖК структурно, поля в evidence останутся пустыми. explicit_token_address — самый уверенный путь, БЕЗ изменений с первого прохода (явный маркер + гео-кластер объявлений Крыши). multi_source_evidence — любой другой сигнал (даже явный токен из homeportal/krisha-очередей не поднимает выше этой reason) — решает человек (тот же случай, что AUSTRIA в granularity policy — она и в этой очереди по homeportal-сигналу, ожидаемо). address_diverge_no_token — reason первого прохода (до многоуровневости), остался у старых записей, поведение то же, что multi_source_evidence. manual — кнопка ниже/на карточке ЖК. Подтверждение исполняет playbook (создаёт/находит дочерний complex_id по имени, provenance split_from/matched_by='unravel') — без структурированных кластеров объявлений подтверждение просто фиксирует статус, разнесение — руками.
