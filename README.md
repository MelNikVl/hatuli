сохраняется. [Стратегия и условия переходов](docs/rental_strategy_20261016.md).

Арендный модуль опубликован **16.10.2026**: [калькулятор субаренды](https://hatuli.ai-groundtruth.com/rental/scanner), [посуточный индекс](https://hatuli.ai-groundtruth.com/rental/daily), сценарная net-доходность, фильтры и Buyer Bot. Готовность рыночных срезов проверяется отдельно; мебель и субарендная доставка закрыты до доказательств. [Отчёт выпуска, тесты и ограничения](docs/rental_module_release_20261016.md).

Система автоматически собирает данные об объявлениях продажи и аренды квартир,
считает для каждого объекта многофакторный Deal Score, строит тепловые карты
города (цены, аренда, шум, транспорт, хайп), анализирует новости недвижимости,
обогащает данные о ЖК/застройщиках из официальных реестров и помогает принять
решение о покупке — с локальным (гексагональным) сравнением цены, анализом
торга по реальным аналогам, рейтингом ЖК/застройщиков и скором
локации ЖК.

**Хранилище данных — PostgreSQL** (единственный канонический источник; SQLite
`bot.db` — легаси от Telegram-бота, не используется). Веб-панель на FastAPI,
фоновые systemd-сервисы, кроны оркестратора Hermes.

Приватные запросы арендного пилота хранятся отдельно в SQLite-очереди;
рыночные данные и объявления остаются в PostgreSQL.

## Что умеет

### Аналитика объявлений
- **Сбор данных о продаже и аренде** — квартиры (комнатность, площадь, этаж,
  цена, координаты, фото-ссылки, описание), история изменения цены, признак
  ухода объявления в архив. Синхронизация из Krisha через systemd-сервисы
  (продажа 30–120 мин, аренда 5–15 мин).
- **Deal Score v4** — единый скор 0–100 по четырём взвешенным факторам (цена
  vs локальный рынок, локация+инфраструктура, качество ЖК, доходность/
  ликвидность), с «уверенностью» — какая доля факторов посчитана на реальных
  данных. Риск (этаж/тип продавца и т.п.) считается отдельным компонентом
  `components.risk`, но с 2026-08-14 в сам скор НЕ подмешивается (вес 0,
  см. `docs/verdict_strategy.md` §5) — вместо этого риски объекта (включая
  Deal Score risk-флаги, но не только их) собраны в отдельный «паспорт
  рисков» (`bot/core/listing_risks.py`) и показываются самостоятельным
  блоком в карточке объявления, не растворяясь в среднем балле.
- **Гексагональный анализ цены** — ожидаемая цена/м² строится из медианы по
  своему гексагону + 6 соседних + городу (с учётом класса ЖК), а не по всему
  району целиком.
- **Анализ торга** — сравнение с реальными аналогами (гексагон+кольцо,
  комнаты, площадь ±15%, класс ЖК), с честной пометкой при нехватке данных.
- **Классификация отделки** — черновая / с отделкой / с мебелью по тексту
  объявления (эвристика; опциональный платный LLM-анализ).
- **Реальные просмотры** — `krisha-viewcount.service` (Playwright/headless
  Chromium): считывает число просмотров объявления (статичный HTML Крыши
  число не отдаёт, нужен JS/фингерпринт) и копит историю, цикл ~1 ч.
- **Дедупликация, геопривязка, проверка актуальности** (архив).
- **Исторические снимки для вердикт-стратегии** — ежедневные
  `listing_snapshots` (цена/просмотры/активность), `outcome_labels`
  (исходы: исчезло за 30 дн / снижение цены / пережило 90 дн / TOM /
  скорость просмотров) и `deal_score_snapshots` (история Deal Score) —
  сырые данные для будущих outcome-моделей (Фаза C).

### ЖК и застройщики
- **Обогащение данными о ЖК/застройщиках** — класс жилья, теххарактеристики,
  застройщик — из Korter.kz, Homsters.kz, Krisha. Интервал обхода 5 дней
  (настраивается на вкладках парсеров).
- **Официальные данные homeportal.kz (реестр КЖК)** — `homeportal_scan.py`
  (щадящий: 1 ЖК / 90 с) тянет 619 объектов Астаны: этажность, число квартир,
  лифты, БИНы застройщика/технадзора/уполномоченной, даты строительства.
  Блок «Официальные данные» — на страницах ЖК и застройщиков.
- **Статус строительства** — для ЖК с карточкой Крыши сканер
  `krisha_complex_scan.py` вытаскивает `build_status` («Строящийся» /
  «Сдан в эксплуатацию») и `deadline` («Срок сдачи: II кв. 2026»).
- **Housing-class** — классификация ЖК с характеристиками: цена за м²,
  этажность, высота потолков, лифты (кол-во и тип), число квартир
  (таблицы `complex_tech_specs`, `housing_class_test`, ручной ввод на
  странице `/admin/analytics/complexes`).
- **Класс старого фонда** — `housing_class_pre2000_backfill.py`: одноразовый
  backfill для ЖК без класса: `year_built < 2000` → `'эконом'` (миграция 073,
  метка `housing_class_source='pre2000_heuristic'`). Эвристика закрывает малую
  часть дыры покрытия (~2% записей — Астана застраивалась в основном после
  2000 г.), применяется как есть, без таймера.
- **Отслеживание изменений источников** — `source_changes`/`source_runs`:
  дифф новых/изменённых ЖК по каждому прогону Korter/Homsters (вкладки
  парсеров: изменения за 1/3/7/30 дней, длительность обходов).
- **Банки и ипотека** — 14 банков, 27 ипотечных программ
  (`/admin/banks`, `/admin/banks/{slug}`): ставки, ГЭСВ, взносы, условия,
  ссылки на источники.
- **Калькулятор ипотеки** (`/admin/mortgage-calculator`) — ежемесячный
  аннуитетный платёж по каждой подходящей программе (цена/ПВ/срок/тип жилья).
- **Оценка банка** — показатель в блоке ипотеки (большой попап карты,
  страница объявления). Пока заглушка = наша расчётная «реальная цена»
  (`bargain.target_price`), см. `/admin/info#bank-estimate`.

### Фото и планировки
- **Детекция планировок (SigLIP)** — `floorplan_scan.py`: гибрид OpenCV-эвристики
  (быстрый фильтр по насыщенности/белому/чёрным линиям) + SigLIP-классификатор
  (ViT-B-16, ~9 img/s на CPU), различает план квартиры от обычного фото.
  Найденные планы — блок «План квартиры» в карточке объявления, прогресс —
  на странице `/admin/analytics/photo-analysis`.
- **Чистка мусорных фото (SigLIP-эталоны)** — эталонные «мусорные» картинки
  (заглушки/реклама) сравниваются с фото объявлений (порог 0.82); найденные
  URL попадают в `blocked_photo_urls` и вычищаются из всех объявлений одним
  SQL (сделано для ~15 тыс. объявлений). Интегрировано в `floorplan_scan.py`.

### Карты города
- **Тепловые карты** на дашборде (13 режимов): цены продажи/аренды, цена за м²,
  доходность, внешний шум (OSM-дороги), транспортная доступность, хайп по
  новостям, плотность населения, количество объявлений, снос домов,
  инфраструктура, новизна домов и **преступность**.
- **Преступность** — официальный портал КПСиСУ ГП РК (`gis.kgp.kz`, слой
  KPSSU/crime): 250k+ записей по Астане с 2015 г., ежедневное обновление
  (`krisha-crime.timer` 06:30). Гексы 150 м: оттенок = тяжесть (0–4),
  непрозрачность = количество; в настройках карты — выбор периода
  **месяц / полгода / год**.
- **Транспортная доступность** — 5 409 гексов (ребро 100 м) со скорингом:
  ЛРТ-станции ≤1 км (вес 0.75) + автобусные остановки ≤500 м (вес 0.4).
- **Точки притяжения** — 75+ достопримечательностей и 24 точки ЛРТ
  (действующие станции + плановые линии с примерными сроками запуска).
- **Карта ЖК** (`/admin/complexes`) — все ЖК с подписями: название на синем
  фоне, число активных объявлений, класс жилья; пометки «Крыша/Homeportal/
  Объявления» — какие данные у ЖК есть.

### Локация ЖК («🗺 Локация»)
- **Блок «🗺 Локация» на карточке ЖК** (`/complex/{id}`) — скор локации 0–100
  с раскладкой по группам факторов (транспорт, инфраструктура, шум, зелень,
  риски): каждая группа кликабельна и раскрывает конкретные находки.
  Бэкенд — `/admin/api/complex/{id}/location-detail`.
- **Риск-бейджи** — плашки под скор-картой, только при наличии оснований:
  «снос в 400 м», «предложение выросло за квартал», «срок экспозиции растёт»
  (принцип Unknown ≠ average: нет данных — нет плашки).
- **Карта со слоями** — переключаемые слои на карточке ЖК: POI
  (остановки/магазины/аптеки…), зона сноса (`demolition_houses`, радиус 1 км),
  тепловая карта плотности предложения (соседние гексагоны `hex_market_stats`).
- **Таймлайн динамики** — график `price_drop_share_30d` (доля объявлений со
  снижением цены) по дням из `complex_stats_history` (копится с 2026-08-14).
- **Инфраструктура (Фазы L1/L2, завершены 2026-08-14)** — ежедневные снимки
  `complex_stats_history` (`avg_dom_days`, `price_drop_share_30d/60d`) и
  `hex_market_stats` (плотность предложения по гексагону), ежемесячный
  пересчёт `complex_location_scores`, ежедневный healthcheck зеркал Overpass
  (`krisha-osm-healthcheck`) с общим `admin_alert`.

### Хайп-аналитика по новостям (LLM)
- **Принцип**: хайп локаций строится **только из новостей** — LLM (DeepSeek)
  читает заголовки+выжимки статей и извлекает упоминания конкретных локаций
  (ЖК, станции ЛРТ, парки), присваивает рейтинг 0–100 и причину.
- **Геопривязка**: станция ЛРТ → все чистые ЖК в радиусе 500 м (рейтинг
  убывает с расстоянием); **парк в положительном контексте** (открытие/
  благоустройство/реконструкция) → ЖК в радиусе 700 м; иначе — точный ЖК
  по имени. ТРЦ-«парки» отсекаются.
- **Цикл**: сбор новостей 1×/день 08:30 (Google News RSS + Playwright),
  Threads — каждый час, медиа-скан СМИ — 5×/день (8/11/14/17/20),
  **LLM-анализ — 21:00** (`krisha-hype-news.timer`, флаг `AI_HYPE_NEWS`).
- **Хранение**: `hype_tracker` (отдельная БД) — `hype_resources`,
  `hype_snapshots`, `hype_resource_runs`, `hype_locations` +
  `hype_location_history`, `news_analysis_runs`.

### Новости
- Раздел `/admin/news` — ежедневный дайджест новостей недвижимости Астаны
  (только СМИ): карточки с фото, выжимка, страница новости `/admin/news/{id}`.
- **«Анализ новостей»** — графики: новости по дням, токены LLM-анализа.

### Гигиена данных (автоматическая)
- **Дедуп ЖК** — `complexes_cleanup.py`: нормализация имён (вкл. казахские
  буквы ә→а, ұ→у, қ→к), кластеры-дубли по координатам/имени, каноническая
  запись, перепривязка объявлений, `is_garbage`. Очищено ~900 мусорных ЖК.
- **Сопоставление с Крышей/homeportal** — `match_601.py`,
  `match_homeportal_531.py`: фаззи-матчинг названий (порог 0.85+, короткие
  имена — только точное) для проставления `krisha_url` и `matched_complex_id`.
- **Отвязка улиц** — `street_audit_daily.py` (cron 04:30): находит «ЖК»,
  где ≥60% объявлений имеют название ЖК в адресе (= улица), помечает
  `is_street`, отвязывает объявления, пересчитывает координаты.

### Прочее
- **Бэкапы** — `backup_hatuli.py` (локально на Windows): дампы
  krisha_bot + hype_tracker + архив проекта (без venv/.git/фото-кэша),
  ротация 5, ежедневно 03:00; каждая запись — в `backup_history` со

- **Google Sheets sync** — квартиры, аренда, инвест-объекты.

## Deal Score v4 (0–100)

| Компонент | Вес | Источник |
|-----------|-----|----------|
| Цена vs локальный рынок | 40% | Гексагон+кольцо+город, с поправкой на класс ЖК и потолки |
| Локация+инфраструктура | 20% | Цена гексагона vs города + POI рядом |
| Качество ЖК | 20% | Класс/год/рейтинг, либо перцентиль цены в сегменте |
| Доходность+ликвидность | 15% | Yield по rental_index + число аналогов в ЖК |

Риск (этаж 1й/последний, риелтор vs собственник и т.п.) в сумму НЕ входит
(вес 0 с 2026-08-14, `docs/verdict_strategy.md` §5) — считается отдельным
компонентом `components.risk` и показывается самостоятельным «паспортом
рисков» (`bot/core/listing_risks.py`) в карточке объявления, см. выше.

Веса настраиваются в `/admin/settings`. Полное описание — вкладка «Инфо».

## Хайп-методика (кратко)

1. Сбор: новости (08:30) + Threads (ежечасно) + СМИ-скан (5×/день) + снимки (8:00/20:00).
2. LLM-анализ в 21:00 (`news_analyze.py`): определяет упомянутые локации и рейтинг 0–100.
3. Геопривязка: станция ЛРТ → ЖК в 500 м; парк (в хорошем смысле) → ЖК в 700 м;
   иначе — точный ЖК по имени (фаззи, казахская нормализация).
4. Запись в `hype_locations` + история → карта обновляется автоматически.
5. Отчёт в чат: N новостей из M источников (в т.ч. Threads K), токены, топ-3 локации.

Подробности — вкладка «🔥 Хайп» на странице `/admin/info`.

## Установка

```bash
# 1. Клонировать
git clone git@github.com:MelNikVl/hatuli.git
cd hatuli

# 2. Виртуальное окружение
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 3. PostgreSQL
sudo apt install postgresql
sudo -u postgres createuser -P krisha
sudo -u postgres createdb -O krisha krisha_bot
sudo -u postgres createdb -O krisha hype_tracker   # для хайп-аналитики
psql -U krisha -d krisha_bot -h localhost -f bot/db/schema.sql
# + миграции hype_tracker (таблицы hype_*, news_analysis_runs)

# 4. Конфигурация
cp .env.example .env
# Заполнить .env: DATABASE_URL, ADMIN_PASSWORD, DEEPSEEK_API_KEY и т.д.

# 5. Запустить сервисы
sudo cp *.service *.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now krisha-web krisha-apartments krisha-rental \
    krisha-geobind krisha-viewcount krisha-homsters krisha-korter
```
