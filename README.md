# Hatuli — аналитическая платформа инвестиций в недвижимость Астаны

Система автоматически собирает данные об объявлениях продажи и аренды квартир,
считает для каждого объекта многофакторный Deal Score и помогает принять
решение о покупке — с локальным (гексагональным) сравнением цены, анализом
торга по реальным аналогам, тепловыми картами города и рейтингом ЖК/застройщиков.

## Что умеет

- **Сбор данных о продаже и аренде** — квартиры (комнатность, площадь, этаж,
  цена, координаты, фото, описание), с историей изменения цены и признаком
  ухода объявления в архив.
- **Deal Score** — единый скор 0–100 по пяти факторам (цена vs локальный
  рынок, локация+инфраструктура, качество ЖК, доходность/ликвидность, риск),
  с "уверенностью" — какая доля факторов посчитана на реальных данных, а не
  на дефолте.
- **Гексагональный анализ цены** — ожидаемая цена/м² строится из медианы по
  своему гексагону + 6 соседних + городу (с учётом класса ЖК, когда он
  известен), а не по всему району целиком.
- **Анализ торга** — сравнение с реальными аналогами (тот же гексагон+кольцо,
  комнаты, площадь ±15%, класс ЖК), с честной пометкой, если данных рядом
  мало или класс ЖК не определён.
- **Классификация отделки** — черновая/с отделкой/с мебелью, по тексту
  объявления (текстовая эвристика; более точный AI-анализ через LLM —
  опциональный платный шаг).
- **Реальные просмотры** — отдельный фоновый сервис на headless-браузере
  считывает настоящее число просмотров объявления (не через API — такой API
  не публичный) и копит историю по времени.
- **Обогащение данными о ЖК/застройщиках** — класс жилья, репутация,
  просрочки сдачи, судебные иски — из внешних открытых источников,
  сопоставляется с объявлениями по названию ЖК.
- **Геопривязка** — координаты и класс ЖК с детальной страницы объявления,
  геокодинг адреса как резервный вариант (с защитой от случайных совпадений
  вне города и от адресов без номера дома, которые нельзя точно геокодировать).
- **Проверка актуальности** — периодически перепроверяет активные объявления
  на признак снятия с публикации/продажи, помечает архивные.
- **Тепловые карты города** — цены продажи/аренды, инфраструктура (школы/сады),
  приблизительный уровень шума (по данным OSM о дорогах и их загруженности),
  покрывающие всю территорию города, а не только точки с данными.
- **Google Sheets sync** — таблицы с квартирами, арендой и инвест-объектами.
- **Веб-панель администратора** — карта, аналитика (цены, торги, покрытие
  данными по этажам/просмотрам, ушедшие в архив, дубли), рейтинг ЖК и
  застройщиков, журналы, настройки.

## Базы данных (PostgreSQL)

| Таблица | Описание |
|---------|----------|
| `apartment_listings` | Квартиры на продажу — данные, скоры, история цены |
| `rental_listings` | Сырые объявления аренды |
| `rental_index` | Агрегированные ставки аренды по ЖК/району/комнатности |
| `complexes` | Жилые комплексы — класс, год, застройщик, рейтинг |
| `developers` | Застройщики — репутация, просрочки, суды, сайт |
| `price_history` | История изменения цены по объявлению |
| `city_roads` | Точки дорог (полосы/тип) для карты шума |
| `city_poi` | Школы/сады/вузы для инфраструктурного слоя |

## Deal Score v4 (0–100)

| Компонент | Вес | Источник |
|-----------|-----|----------|
| Цена vs локальный рынок | 40% | Гексагон+кольцо+город, с поправкой на класс ЖК и высоту потолков |
| Локация+инфраструктура | 20% | Цена гексагона vs города + POI рядом |
| Качество ЖК | 20% | Класс/год/рейтинг, либо перцентиль цены в сегменте, если класс не известен |
| Доходность+ликвидность | 15% | Yield по rental_index + число аналогов в ЖК |
| Риск | 5% | Этаж (1й/последний), риелтор vs собственник |

Веса настраиваются в /admin/settings. Полное описание — на вкладке "Инфо" веб-панели.

## Установка

```bash
# 1. Клонировать
git clone https://github.com/MelNikVl/hatuli.git
cd hatuli

# 2. Виртуальное окружение
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 3. PostgreSQL
sudo apt install postgresql
sudo -u postgres createuser -P krisha
sudo -u postgres createdb -O krisha krisha_bot
psql -U krisha -d krisha_bot -h localhost -f bot/db/schema.sql

# 4. Конфигурация
cp .env.example .env
# Заполнить .env: DATABASE_URL, ADMIN_PASSWORD, при необходимости — ключи
# внешних сервисов (LLM для AI-анализа текста, Telegram-бот для алертов)

# 5. Google Sheets (опционально)
# Добавить google_creds.json (сервисный аккаунт Google Cloud),
# открыть таблицу → Поделиться → добавить email сервисного аккаунта

# 6. Запустить сервисы
sudo cp *.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now krisha-web krisha-apartments krisha-rental \
    krisha-viewcount krisha-geobind
```

## Веб-панель

```
/admin              — карта, фильтры, тепловые карты
/admin/analytics    — таблица квартир со скорами, аналитика (просмотры, этажи, архив)
/admin/complexes    — рейтинг ЖК
/admin/developers   — рейтинг застройщиков
/admin/info         — документация модели скоринга
/admin/settings     — веса Deal Score, лимиты сбора данных, монетизация
```

## Переменные окружения

```env
DATABASE_URL=postgresql://krisha:password@localhost/krisha_bot
ADMIN_PASSWORD=               # Пароль веб-панели
PARSER_ENABLED=0              # 0 = сбор продаж выключен
AI_TEXT_ANALYSIS=0            # 1 = включить платный AI-анализ текста (нужен ключ LLM)
```

## Планы

- Личный кабинет пользователя (избранное, уведомления, привязка Telegram)
- AI-анализ фото (состояние ремонта — как дополнение к текстовой эвристике)
- Расширенный рейтинг ЖК (отзывы, тайный покупатель)
- Мониторинг ресурсов сервера в /admin/settings
