## Почему не обновился файл рынка

После успешного выпуска вызван `scripts/publish_market_comparison.py`.
Он завершился с ValueError и сохранил предыдущую публикацию. Read-only
диагностика через `run(..., dry_run=True)` подтвердила отсутствие свежей
первички, а не проблему новой карточки:

- Время диагностики: 2026-10-15T03:05:52.664626+00:00.
- `primary_count`: 0; `secondary_count`: 20 198.
- `primary_available_recent`: 0; `primary_stale_available`: 11 724.
- `krisha_primary_recent`: 1 019; `secondary_recent`: 21 373.
- Проверка издателя: оба рынка должны присутствовать; прежний файл сохранён.

Фактический systemd `krisha-newbuild.timer` содержит
`OnCalendar=Mon *-*-* 06:00:00`, `RandomizedDelaySec=30m`, `Persistent=true`.
Последний обход 12 октября 06:24:58–06:36:06 UTC+5 завершился rc=0;
следующий назначен на 19 октября. К четвергу все его наблюдения вышли за
72 часа. Причина — несогласованные расписание сбора и допуск свежести.

Сохранённый файл рынка: `generated_at=2026-10-14T21:20:00.115083+00:00`,
то есть 15 октября 02:20; 6 819 первичных и 20 604 вторичных вариантов,
2 457 наблюдаемых гексагонов. Публичная страница явно показывает время
02:20; сегодняшний выпуск не означает, что рынок заново подтверждён в 08:04.

Фильтр 72 часов и требование обоих рынков сохранены. Старые данные не
помечались свежими. Импортёры вызывают init_pool и пишут в БД, поэтому в
рамках этого задания с запретом таких операций не запускались. Тестов,
миграций, фикстур и ручных UPDATE против рабочей БД не было.

Следующая отдельная задача — перевести реальный сбор первички на ежедневный
либо 48-часовой цикл с учётом нагрузки источников; проверить по каждому
источнику количество реально увиденных юнитов и ошибки записи, затем
выпустить новый файл рынка. Один rc=0 не доказывает полноту покрытия.
Устаревший `load_svoydom.py`, удаляющий юниты перед загрузкой, для этой
задачи не запускать.

## Следующие задачи качества

- У 1012894581 основание отбора — сохранённое снижение на 1 млн ₸,
  график есть. В «Почему в подборке» сейчас только отклонение +1% от
  медианы. Нужно связать объяснение с уже показанным событием снижения;
  отрицательная разница с рынком сама по себе преимуществом не является.
- В отдельной изолированной проверке без БД обнаружено несогласованное
  округление в построителе рынка: цена за м² вычисляется по исходной
  площади, площадь сохраняется с двумя знаками. Синтетический пример
  20,004 м² / 60 млн ₸ отклоняется собственным валидатором. Это отдельный
  воспроизводимый дефект, не причина сегодняшней остановки при нулевой
  первичке. Исправлять нужно вычисление, сохраняя строгость валидации.
