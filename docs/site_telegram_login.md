# Переход из бота на сайт после входа

После подтверждения Telegram бот показывает кнопку «Открыть Hatuli». Она
открывает `/auth/telegram#token=…`; сайт завершает вход и переводит на `/map`.
Истёкшая или использованная ссылка предлагает повторить вход через `/cabinet`.

Исходный токен вкладки и токен кнопки независимы: автоматический вход в
первой вкладке не расходует ссылку для встроенного браузера Telegram. Каждый
токен одноразовый, действует 10 минут; срок кнопки начинается при подтверждении
в боте. Подтверждение привязывает исходный токен к одному Telegram ID атомарно.
Заблокированный или удалённый пользователь не может обменять ссылку на сессию.

Кнопка выдаётся только в личном чате. Фрагмент не передаётся в HTTP URL;
страница сразу удаляет его из адреса и отправляет в JSON POST. Просмотр ссылки
через GET не создаёт сессию. Cookie `site_session` имеет HttpOnly, Secure на HTTPS,
SameSite=Lax и Path=/; ответы входа запрещают кеширование и передачу Referer.

Домен кнопки задаётся `HATULI_PUBLIC_URL` (HTTPS origin, без пути и параметров).
По умолчанию — `https://hatuli.ai-groundtruth.com`. Миграции не требуются.
При обновлении перезапускаются `krisha-web.service` и `krisha-sitebot.service`.

«Админка» — первый пункт общей навигации при подтверждённой `admin_session`.
Вход посетителя через Telegram сохраняет существующую административную cookie;
Telegram username, подписка или full_access не заменяют административную роль.

Проверки: `tests/test_telegram_site_login.py`, `tests/test_admin_menu_visibility.py`,
`node --test tests/test_telegram_login_client.cjs`. Проверки гонок SQL в
`tests/test_site_auth_exchange_sql.py` требуют отдельную временную базу с именем
`hatuli_auth_test_<id>` через `HATULI_AUTH_TEST_DATABASE_URL`; они никогда не
используют `DATABASE_URL`, миграции проекта или рабочие таблицы.
