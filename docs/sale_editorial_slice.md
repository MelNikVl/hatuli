# Приватный аудит продажи перед редакционной аналитикой

`scripts/export_sale_editorial_slice.py` читает текущую активную продажу с
`last_seen` не старше 72 часов, без изменения PostgreSQL или публичных файлов.
Соединение имеет `default_transaction_read_only=on`; все ограниченные чтения
идут в одной `repeatable_read` транзакции с проверкой обоих параметров.
Превышение лимита строк/справочников приводит к отказу, а не усечённым медианам.
Пулы приложения, миграции, источники объявлений и фотографии не вызываются.

```bash
venv/bin/python scripts/export_sale_editorial_slice.py \
  --output var/editorial-audit/2026-10-19/sale-slice-v1.json
```

Экспорт не перезаписывает существующий файл; каталог/файл создаются с
0700/0600. Отдельное `--source-checks` допускает только явно переданные
нормальные браузерные квитанции не старше двух часов. Отсутствие такой
квитанции не превращает строку в проверенную браузером.

## Схема версии один

- `kind=private_sale_editorial_slice`, `schema_version=1`, `generated_at`,
  `exported_at`: действительные времена расчёта и окончания экспорта.
- `policy`: вторичка до 100 млн ₸, 72 часа, группы от десяти, площадь
  ±15% от явно заданного якоря, одинаковая комнатность и сохранённая отделка.
- `input_rows`: полный ограниченный срез разрешённых полей с аннотацией
  существующих identity helpers. Нет описаний, контактов и документов.
- `decisions`: ID, допуск, перекрывающиеся причины отказа и уровень проверки.
  `counts` отдельно содержит количество исключённых строк и счётчики причин;
  перекрывающиеся причины не складываются в число исключённых квартир.
- `known_source_conflicts`, `known_source_conflicts_sha256`, `held_property_ids`:
  замороженное отрицательное доказательство по 1012143050 («Акерке 2» /
  «Возрождение», P1 №81). Оно действует независимо от сохранённого имени.
  Другие публикации того же property ID также не входят в обе медианы,
  даже если исходное объявление уже ушло из активного окна. Это исключение,
  а не исправление каталога. Для снятия запрета нужна отдельная проверка.
- `accepted_rows`: допущенные строки после существующего canonical/house/
  review gate и консервативного устранения повторных property ID. Строка без
  property ID не становится доказанно уникальной физической квартирой.
- `ready_profiles`: только подтверждённые физические property ID, без
  неизвестной отделки, по району и каноническому ЖК/дому × комнаты × площадь.
- `descriptive_cohorts`: тот же условный срез наблюдаемых предложений, включая
  provisional/неизвестную физическую идентичность. `ranking_ready=false`;
  `quality_status=physical_uniqueness_not_fully_confirmed`. Это не рейтинг
  рынка или доказательство, что все дубли найдены.
- Обе группы имеют `n_unique_source_after_conservative_dedup`,
  `n_distinct_property_ids`, `n_confirmed_physical`, `n_observations`, медианы
  и P25/P75 общей цены и цены/м², список ID и фактический диапазон `last_seen`.
  Якорные диапазоны площади перекрываются и не складываются.
- `read_only_audit`, `implementation_sha256`: размеры справочников и SHA256
  фактически выполненных файлов. В stdout только агрегированный итог и
  SHA256 экспортного JSON, без исходных объявлений и DSN.

Наличие адреса/каталожной связи — проверка сохранённых данных, не осмотр
дома, подтверждение собственности или сегодняшняя браузерная проверка
всех аналогов. Отделка совпадает как поле БД, качество ремонта по фото этим
аудитом не устанавливается. Первичка исключена и требует отдельного аудита
юнитов. `publication_rights=not_cleared` сохраняется: экспорт сам по себе
не разрешает публикацию исходных данных. Цены договоров, спрос, прогнозы
сделки и доходность не вычисляются. Код не меняет ежедневные подборки.
