# Снятие устаревшего дома при свежем изменении источника — 20.10.2026

Статус: кандидат, публикация и общий CI ещё не подтверждены.

## Выбор улучшения

Актуальная база сервера и master на старте: `cc8d6d8`. Вчерашний
[аудит идентичности](identity_status_20261019.md) обнаружил путь: свежие
ЖК/адрес сохраняются, но `resolved_house_id` остаётся прежним, если следующий
resolver не нашёл новый дом или у нового ЖК нет детей. Правило `house` имеет
приоритет в `complex_binding`; старое производное значение может восстановить
опровергнутую принадлежность и повлиять на аналоги/характеристики.

Первичные источники проверены 20.10.2026:

- [Korter — новостройки Астаны](https://korter.kz/новостройки-астаны): поиск по
  районам/ЖК, каталожные карточки и карта дают местный ориентир для навигации
  по физическим объектам. Это свойства продукта, не независимая проверка
  полноты или точности каталога. Утверждения справочного текста о составе
  районов города не использованы как актуальная административная статистика.
- [Zillow — Zestimate](https://www.zillow.com/zestimate/): данные объекта,
  сопоставимые предложения/сделки и неопределённость влияют на оценку;
  исправленные характеристики могут менять результат. Это описание модели
  конкурента, не обещание такой же точности для Хатули.
- [Google — BreadcrumbList](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb):
  полезная иерархия помогает навигации и интерпретации страницы. Доработка
  разметки рассмотрена как следующий шаг видимости; в этом выпуске SEO не меняется.
- Krisha valuation в этом запуске вернула timeout; вчерашние сведения не
  выданы за свежую успешную проверку.

Вывод для Хатули: сначала прекратить перенос старого дома в обновлённые
исходные данные, затем оценивать расширение аналогов и поисковой видимости.
Это инженерный вывод из текущего дефекта и продуктовых примеров, не
количественный отчёт о мировом рынке или ценах Казахстана. Новая модель
прогноза без подтверждённых исходов не добавлялась.

## Контракт

`sale_detail_persistence.DETAIL_UPDATE_SQL` одним SQL-запросом блокирует
текущую строку, сохраняет принятые исходные поля, снимает зависимые привязки,
журналирует переход и обновляет фактическое время успешного наблюдения.

- Только принятый по времени patch может инвалидировать привязку. Пропущенный
  ключ, неуспешная попытка и поздний ответ не являются новым свидетельством.
- Изменение наблюдённых `complex_name`/`complex_url` снимает прежний complex ID.
- Изменение `complex_name`, `complex_url`, `address`, `description`, `lat` или
  `lon` снимает `resolved_house_id`, метод и описание прежнего основания.
  Сравнение точное, включая дроби и литеры; косметическое изменение также
  консервативно требует повторного разрешения дома.
- Для привязок `house`/`geo` изменение этих оснований снимает и complex ID.
  Независимый `url`/`name` ID сохраняется при изменении только адреса/описания/
  координат. Проверка источника не назначает новый ID и не создаёт алиас.
- Переход попадает в `listing_complex_resolution_log` с предыдущим ID,
  методом, домом и временем наблюдения. Полный текст описания туда не копируется.
  При сохранённом независимом complex ID журнал фиксирует снятие дома без
  ложного заявления смены комплекса. Ошибка журнала откатывает весь patch.
- Следующий штатный resolver может назначить новое значение. Если результата
  нет, прежний дом больше не продолжает выглядеть подтверждённым. Старый
  derivation не может перезаписать новый источник благодаря существующей
  проверке `source_details_checked_at`/`last_seen` в сборщике.

Это применяется общим writer к основному сборщику и `full_sweep`. Форма
источника, бюджеты запросов, CAPTCHA/cooldown и правила нового матчинга не
изменены. Миграции и массовое исправление старых строк не требуются.

## Проверка и ограничения

- На старом SQL все восемь новых сценариев свежего изменения сохраняли
  прежний дом: восемь ожидаемых падений regression на одноразовом PostgreSQL.
- Новый код: 95 passed в persistence, native PostgreSQL, refresh и binding.
  Покрыты смена ЖК без детей, URL, адресов `6/1` → `6/2`/`6Б`, текста/гео,
  явный null, неизменившиеся/пропущенные поля, ошибка/устаревший ответ,
  сохранение независимого complex ID, идемпотентность и полный rollback
  при отказе журнала. Один прежний тест обновлён под разрешённую инвалидацию;
  импорт произвольного нового ID по-прежнему не допускается.
- Тесты БД выполнялись только в Docker PostgreSQL 15, localhost:15480,
  `hatuli_test`, временные таблицы и rollback. Миграции с нуля — только там.
  Первый запуск пришёлся на инициализацию контейнера и дал reset соединения;
  повтор после готовности успешен. Это не ошибка рабочей БД.
- Рабочий аудит — прямой asyncpg, `default_transaction_read_only=on`,
  repeatable-read readonly, statement timeout 5с, lock timeout 1с. На срезе
  40 033 активных строк, виденных за 72ч, у 342 сохранён дом, и у 342
  complex_resolution=house. Включает дубли; это заполненность, не 342 ошибки
  и не число независимых квартир. Нужные поля существующего журнала доступны.

Исторические ошибки без свежего наблюдения, старые property links и полная
строгость всех downstream-потребителей этим выпуском не исправлены.
Текущие снимки подборок/аналитики не пересчитываются. Рост точности прогнозов
и посещаемости не измерен. Метрика установлена вчера; подтверждённого отчёта
людей/день в этом запуске нет. Цель 1000 пользователей/день остаётся целью.
