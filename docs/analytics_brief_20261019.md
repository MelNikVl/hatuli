# Короткая аналитика и линейные графики

Новое требование владельца от 19.10.2026 заменяет прежний ориентир
450–650 слов для следующих выпусков и разрешает обновить сегодняшнюю пару.
Публичные адреса статей сохраняются.

## Редакционный формат

- `editorial_format="brief"`: целевой объём 150–250 слов, технический допуск
  120–350; короткий лид, два–три вывода, два–четыре небольших раздела.
- Ровно два графика реальной помесячной динамики. Каждый — один показатель,
  город/сегмент, единица и `series_id`; даты идут строго по возрастанию,
  без повторного месяца. У сегодняшних четырёх рядов по шесть точек.
- Данные текста и графиков ссылаются на один проверенный digest. Цены
  предложений, месячные средние и завершённые периоды не становятся ценами
  конкретной сделки, сегодняшней ценой квартиры или прогнозом.
- Независимые районы, ЖК и разные показатели нельзя соединять линией как
  временной ряд. Старые сравнения остаются несвязанными точками/таблицей;
  настоящий старый timeline отображается линией. Старый стандартный формат
  остаётся валидным, его полный текст доступен по раскрытию.
- Периоды, единицы, источник и раскрываемая таблица сохраняются. Уровни
  цены и проценты показываются раздельно; неизвестное n не подставляется.
  По горизонтали используются календарные месяцы, пропуск разрывает линию.
  Вертикальная шкала линейная, её диапазон явно подписан.

Готовность локальных рекомендаций по районам/ЖК не меняется от нового
дизайна. Сохраняется [практический редакционный контракт](analytics_practical_editorial_20261019.md):
нужны проверенные независимые сопоставимые объекты, состояние и адресная
принадлежность. Не дописывать географическое преимущество ради короткой статьи.

## Обновление уже опубликованной пары

Исходный `var/analytics-articles/YYYY-MM-DD.json` остаётся неизменным.
Явная редакционная правка создаёт полную пару в отдельном
`var/analytics-article-revisions/YYYY-MM-DD/UTCSTAMP.json`. Новая версия
привязана к SHA256 исходных байтов и содержит реальную причину и
`modified_at`; файл устанавливается атомарно без перезаписи истории.

Публичные readers выбирают последнюю валидную полную редакцию. Ошибочный
SHA, неполная пара, будущее время, несовпавшее имя файла и повреждённый JSON
не подменяют корректную публикацию. Чтение ограничено сотней файлов на дату;
при неполной/чрезмерной выборке остаётся исходная валидная пара.

`published_at` / JSON-LD `datePublished` сохраняют настоящий исходный момент.
Новые источники проверяются относительно `modified_at`, который отдельно
показан читателю и в `dateModified`. Нельзя выдавать новый download за старый
или новую редакцию — за утреннюю публикацию. Отдельный `--local` архив
проверенных собственных исследований этим механизмом не переписывается.

```bash
venv/bin/python scripts/publish_analytics_articles.py \
  --articles PRIVATE/articles-draft.json --digest PRIVATE/official-digest.json \
  --revise --base-sha256 ORIGINAL_SHA256 \
  --reason 'Добавлена помесячная динамика цен' --check-only
venv/bin/python scripts/publish_analytics_articles.py \
  --articles PRIVATE/articles-draft.json --digest PRIVATE/official-digest.json \
  --revise --base-sha256 ORIGINAL_SHA256 \
  --reason 'Добавлена помесячная динамика цен'
```

Для нового дня используется прежний издатель без `--revise`, но с новым
форматом `brief`. Проверка и публикация из готовых файлов не загружают
`.env`, не подключаются к БД и не запускают сбор. Повтор того же содержимого
сохраняет прежний момент редакции.
