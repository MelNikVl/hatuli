# Архив мёртвого кода

Решение заказчика, 2026-08-14 (Часть 2, п.10 — "скоринг волна 2,
гигиена"). Файлы ниже — не удалены совсем (могут быть полезны как
историческая справка о том, как считался скор раньше, или для будущего
сравнения формул), но физически убраны из `bot/core/`, чтобы не
вводить в заблуждение при следующем аудите/найме — все три подтверждены
[`scoring_audit.md`](../scoring_audit.md) §5.2 как имеющие **0 живых
импортёров** во всём репозитории на момент архивации (проверено `grep`
по всему кодовому дереву непосредственно перед переносом).

## `apartment_score.py`

Скоринг вторички (yield/цена-vs-рынок/локация/тип/этаж/supply/рост) —
захардкоженные районы Астаны (Есиль/Алматы/Сарыарка/Байконур/Нура) и
ключевые слова POI. Полностью замещён Deal Score v4
([`bot/core/deal_score.py`](../../bot/core/deal_score.py)) — тот
единственный источник `score_total`/breakdown для вторички сейчас, с
настраиваемыми через `/admin/settings` весами вместо хардкода.

## `apartment_score_v2.py.txt`

Промежуточная версия скоринга (v2/v3) между `apartment_score.py` и
Deal Score v4 — уже была переименована с двойным расширением `.clean`
до этой задачи (не валидное имя Python-модуля — физически не
импортируется), сейчас просто перемещена сюда же для единообразия.
Оставлена как справка о формуле того периода — `score_yield`/
`score_price_market`/... legacy-колонки `apartment_listings` теперь
пишутся как ПРОЕКЦИЯ компонентов v4 (см. докстринг `deal_score.py`),
не независимо этим файлом.

## `hex_price.py`

Гексагональная hedonic-модель (гекс+кольцо+город, `apply_hex_prices()`)
— `apply_hex_prices()` не вызывалась НИГДЕ (только определена), сама
модель (веса 1.0/0.7/0.35, MIN_HEX=3, MIN_RING=5) была **скопирована
заново**, а не переиспользована, внутри `deal_score.py`
(`compute_deal_scores()`) при переходе на v4 — логика не удалилась,
продублировалась в другом файле, и один из двух экземпляров осиротел.
Часть 2, п.9 (та же волна) заодно выделила эти веса в общий
[`bot/core/hedonic_constants.py`](../../bot/core/hedonic_constants.py),
которым `hex_price.py` НЕ пользуется (архивная копия, не живой код) —
если кто-то захочет восстановить инкрементальную адаптацию scoring
из этого файла в будущем, ему нужно будет перейти на общие константы,
не копировать значения в третий раз.

`apartment_listings.hex_price_adj` — колонка всё ещё существует и
заполняется, но **всегда 0** с момента перехода на v4 (`deal_score.py`
пишет константу вместо инкрементальной поправки, см. `scoring_audit.md`
§5.2) — вестигиальна, не путать с живым `hex_deal_index`.
