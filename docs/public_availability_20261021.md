## Добавленный инструмент

```bash
python scripts/check_public_availability.py
```

Требуются Python3.10+ и curl. Используются только четыре фиксированных
анонимных маршрута Хатули. Нет БД, SSH, cookies, логина, повторов и следования
redirect. `curl --disable` отключает пользовательский curlrc. Проверки TLS
сохраняются. Лимиты:8с curl/10с subprocess на маршрут, максимум1MiB тела.
Читается не более лимита+1байт; временные тела удаляются. stdout содержит
только время, target, path, HTTP-код, категорию и длительность, без HTML,
заголовков/cookies, контактов, токенов или stderr транспорта.

Успех требует ожидаемых title/heading текущего маршрута либо namespaced
sitemap с каноническим URL аналитики. Простого HTTP200 недостаточно.
403/429/challenge имеют статус access_blocked: нужен отдельный обычный браузер,
это не утверждение падения origin. Нулевой exit code — все маршруты подтверждены;
1 — хотя бы один не подтверждён. Неизвестная/старая дата подборки проверяется
отдельно: даже доступная страница прошлого выпуска может пройти этот smoke.

Для отдельного сравнения на восстановленном origin:

```bash
python scripts/check_public_availability.py --target local
```

Это только `http://127.0.0.1:8082`, не произвольный URL. Локальный и внешний
результаты различаются по target; локальный успех не подтверждает внешний.

`.github/workflows/public-availability.yml` добавляет **ручной** запуск на
GitHub-hosted Ubuntu. Он не зависит от домашнего сервера, имеет read-only
contents permission и не получает credentials checkout. Отдельный компактный
artifact сохраняется7дней даже при неуспешной проверке и выводится в журнал.
Автоматического расписания и повторов нет. Проверка доступности не включена
в unit CI: известный outage не должен превращаться в регрессию кода.

## Проверки и границы

19 offline unit tests прошли стандартным unittest, включая HTML200 ошибки,
редирект,1033,403/429, XML/namespace, oversized body, DNS/TLS/timeout, удаление
временных файлов, отсутствие stderr/body в receipt, фиксированные маршруты,
соответствие трёх H1 фактическим шаблонам и exit status. Curl в тестах замокан,
рабочая БД и браузер не используются. P2 review о неизвестной XML-кодировке
воспроизведён как LookupError и исправлен: теперь даже такой ответ даёт
unexpected_content и полную JSON-квитанцию с ненулевым exit code. Одна живая локальная серия подтвердила
внешний инцидент, а не восстановление. Общие CI/review/merge фиксируются в PR.

README, отдельный GitHub-журнал, Notion и навыки менеджера/анализа/frontend
актуализированы; все пять навыков валидируются и устанавливаются локально.
Слияние инструмента в master делает его доступным для внешней диагностики,
но не означает установку на недоступный сервер или настройку автолечения.

Следующий необходимый шаг: восстановить питание/сетевую доступность указанного
хоста, проверить фактические HEAD/dirty files/службы и cloudflared. Сначала
сопоставить local/public probes. Затем проверить реальные сегодняшние файлы;
прошлые публикации не передатировать. Перезапускать/перенастраивать сервисы
только по фактам восстановленного хоста, сохраняя cooldown и чужие изменения.
Цена сделки, срок продажи, покрытие рынка и пользователи/день не измерялись.
