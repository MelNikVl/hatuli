## Изменение

- Для точного configured public authority используется HTTPS из
  `HATULI_PUBLIC_URL`; произвольный Host не наследует это разрешение.
  Клиентские X-Forwarded-* не используются новой функцией как источник доверия.
  Действующая обработка trusted proxy самим сервером отдельно не меняется.
- Origin, Fetch-Site, custom-header, content-type, ограничение тела и формат
  токена сохраняются. Сайт получает Secure/HttpOnly/Lax cookie и за TLS proxy.
- GET `/api/auth/status` возвращает только authenticated:boolean, private/no-store,
  no-referrer/noindex. Анонимный запрос не обращается к БД. Общая шапка может
  показать «Кабинет» на публичных страницах без данных профиля и повышения прав.
- Кабинет обрабатывает ошибки старта/опроса, проверяет точный HTTPS t.me deep-link,
  оставляет обычную ссылку при заблокированном popup. Опрос последовательный,
  не дольше10минут/300попыток, запрос ограничен12с; возврат назад и pagehide
  отменяют старый процесс. Кабинет/избранное получают site_user и no-store.
  Сам обмен на странице возврата также прерывает зависший запрос/чтение
  ответа через12с и предлагает свежий вход без повторного погашения токена.
- Ошибки membership API предлагают повтор до upsert/verify; прежний отдельный
  режим недоступного списка участников не расширен. Безопасный журнал содержит
  только этап/класс ошибки, а старт бота — git-хеш. Bare `/start` объясняет,
  что нужна свежая ссылка с сайта и нажатие Start.
- Повтор по той же ссылке, истёкший токен, чужая Telegram identity и блокировка
  не обходятся. Telegram-вход по-прежнему отдельно от административной сессии.
